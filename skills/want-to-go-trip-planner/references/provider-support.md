# 地图与真实交通边界

## 高德（中国大陆）

- 地点文本检索返回候选 POI，分店仍由用户确认。
- 规划矩阵使用高德距离接口缩小计算量。
- 最终每一段调用路径规划 2.0，驾车段读取当前交通相关路线与拥堵状态。
- 驾车、步行、公交、骑行由最终路径接口分别校验。
- 输入坐标必须来自高德地点解析并标为 `GCJ02`。
- 常见中文星期和时间范围会转成结构化营业时段；无法解析时保留原文并要求人工复核。
- 使用目的地六位 `cityAdcode` 查询高德逐日天气；只使用与旅行日期完全一致的预报，不把当前天气误套到未来日期。
- 普通接口抓到的是当前路况，不代表几周后的同一时刻。高德未来路径能力是否可用取决于企业资质和具体 API 权限。

## Google Routes（中国大陆以外）

- 使用 Compute Route Matrix 排序。
- 驾车最终路线使用 `TRAFFIC_AWARE_OPTIMAL`。
- 公交使用服务时刻；步行和骑行使用路线估算。
- 输入坐标必须为 `WGS84`。
- 未来驾车时间由实时与历史交通共同估算，仍不是准点保证。
- 同一 Google Cloud 项目启用 Weather API 后，按住宿起点取得最多10天逐日预报；超出覆盖范围时只提示未知。

## Mock

只用于安装验证和自动测试，以直线距离、道路系数和固定速度生成确定性数据。输出会明确标记：

```json
{
  "provider": "mock",
  "trafficModel": "synthetic-test-data",
  "liveTraffic": false,
  "planningQuality": "test-only"
}
```

不得把 Mock 结果销售或称为真实交通路线。

## 混合交通

`MIXED` 会分别请求允许的交通方式矩阵，过滤过长的步行和骑行段，并加入换乘、停车或叫车缓冲，再为每一段选择方式。它是可解释的启发式选择，不是票价最优或数学全局最优。最终每一段仍调用对应地图路线接口核验。

## 天气与公共假日

- 高德或 Google 返回的预报按 `YYYY-MM-DD` 与旅行日期精确匹配。
- 高降水概率、雷暴、重度降雪、冰冻、高温或严寒会标记天气风险；天气敏感地点可移到未触发风险的日期。
- 公共假日通过 Nager.Holidays 按国家代码和年份查询，只用来标记“这一天需要复核商户公告”。
- 中国调休工作日和商户特别营业必须再对照国务院与商户公告；公共日历不得直接把地点判为开门或关门。
- 预报接口失败或日期超出范围时继续生成带警告的路线，不将当前天气冒充旅行日期天气。

预约、实时排队、商户特定闭店日期和天气敏感性仍来自用户、宿主或商户已核验的结构化事实。没有可靠数据时只提示未知，不编造实时排队或商户特别营业。

## 建议刷新时点

- 制定行程：用旅行日期可获得的历史/未来预测。
- 出发前 24 小时：复核营业状态、预约要求和明显施工。
- 每日出发前：重算当天全部交通段。
- 每段出发前：打开导航链接获取最新路况。
